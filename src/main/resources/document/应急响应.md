# 网络安全知识库 - 应急响应篇

#### 怀疑主机中了木马，应该如何系统排查？
排查应遵循"先隔离、再取证、后处置"的顺序。第一步是在条件允许时将主机从网络隔离（拔网线或在防火墙封禁出站连接），但保持开机以保留内存证据。随后检查自启动项：Windows 可通过任务管理器启动项、注册表 Run 键、服务（services.msc）、计划任务和 WMI 订阅排查异常持久化；Linux 检查 systemd 服务、crontab、/etc/rc.local 和 profile 脚本。接着用 netstat 查看异常外联连接与监听端口，用任务管理器或 ps 定位可疑进程及其可执行文件路径，校验文件数字签名和创建时间。再检查系统账号是否被新增、hosts 文件是否被篡改。处置时应优先通过专业杀毒或 EDR 查杀，手动清除需同时删除恶意文件、启动项和服务，最后修补漏洞、修改可能泄露的口令。整个过程应截图和导出日志留存，便于溯源。

#### 中了勒索病毒后第一时间该做什么？
勒索病毒处置的核心是控制扩散和评估损失，切忌盲目支付赎金。发现后立即断开受感染主机的网络连接，防止横向扩散和更多文件被加密；同时排查同一网段内其他主机是否出现异常，因为勒索通常通过共享目录和漏洞批量传播。不要立即格式化或重启，应先保留勒索信样本、加密文件样本和内存、系统日志，用于判断勒索家族和溯源。通过勒索家族名查询是否存在公开的免费解密工具（如 No More Ransom 项目）。随后从干净的备份恢复数据，恢复前需彻底清除恶意程序、修补初始入侵利用的漏洞并重置所有凭据。平时应落实 3-2-1 备份策略（3 份副本、2 种介质、1 份离线），这是应对勒索最有效的手段。

#### 如何判断服务器是否被入侵？
入侵判断需要结合多维度异常信号。账号方面，检查是否存在未知新增账号、管理员组异常成员、账号在非工作时间的异地登录。进程与网络方面，关注占用异常 CPU 或带宽的进程（可能是挖矿或肉鸡）、陌生的对外连接和非常用端口监听。文件方面，检查 Web 目录下是否出现 WebShell（如异常的脚本文件、一句话木马）、系统命令是否被替换、关键配置和定时任务被篡改。日志是关键依据：Windows 查看安全事件日志中的登录事件（4624、4625），Linux 分析 /var/log/secure、/var/log/auth.log，Web 服务器分析访问日志中的异常请求。若发现确凿入侵痕迹，应按应急响应流程隔离、取证、清除并复盘漏洞入口。

#### 应急响应中如何分析和保留日志证据？
日志分析应先明确时间范围和攻击链，再交叉关联不同来源的日志。取证时遵循"易失数据优先"原则，先采集内存、网络连接、登录会话等断电即失的数据，再采集磁盘文件和系统日志。所有操作尽量避免在原始证据上直接修改，可对磁盘做镜像或对文件做哈希校验以保证证据完整性和可追溯性。Windows 重点分析安全日志、系统日志、应用日志及 PowerShell 历史，Linux 分析 secure、messages、bash_history，Web 分析 access 和 error 日志。通过登录时间、源 IP、执行的命令、访问的 URL 等还原攻击路径。所有证据应记录采集时间、采集人和文件哈希，妥善保存，避免污染。

#### Web 网站被挂马或篡改后如何处置？
Web 挂马处置先从阻断和定位入手。第一时间可临时下线站点或在网关封禁，防止访问者继续受害。然后定位 WebShell 和篡改点，通过文件修改时间、Web 访问日志中的可疑 POST 请求、静态特征和文件完整性比对，找出被上传的后门脚本和被篡改的页面文件。清除 WebShell 后不能就此结束，必须追溯入侵入口，常见入口包括文件上传漏洞、SQL 注入、弱口令、组件漏洞和服务器权限泄露，针对入口修补漏洞并升级组件。同时检查是否存在隐藏账号、计划任务等服务器层面的持久化，重置相关口令。最后从干净备份恢复页面，部署 Web 应用防火墙并加强文件监控，建立定期巡检机制。
