# 网络安全知识库 - 漏洞攻防篇

#### 什么是 SQL 注入，如何防范？
SQL 注入是指应用程序未对用户输入做有效校验或参数化处理，攻击者把恶意 SQL 片段拼接到后端查询中，从而绕过认证、读取或篡改数据库内容，甚至通过数据库提权控制服务器。其本质是"数据被当成了代码执行"。防范的根本措施是使用参数化查询（预编译语句 PreparedStatement），让用户输入始终作为数据而非 SQL 语法参与执行。此外应遵循最小权限原则，限制数据库账号权限，避免应用直接使用高权限账号；对输入做白名单校验和类型约束，对异常字符进行转义；在生产环境关闭详细的数据库报错信息，避免泄露结构；并通过 Web 应用防火墙和定期代码审计、漏洞扫描做纵深防御。

#### 什么是 XSS 跨站脚本攻击，如何防范？
XSS 是攻击者向网页中注入恶意脚本，当其他用户浏览时脚本在其浏览器中执行，可用于窃取 Cookie、劫持会话、钓鱼挂马或篡改页面。按数据来源可分为反射型、存储型和 DOM 型。防范核心是对用户输入和输出进行妥善处理：输出到 HTML 页面时进行上下文相关的编码转义，对特殊字符进行实体化；对富文本等需要保留标签的场景，使用白名单过滤库而非黑名单。同时可通过设置 Cookie 的 HttpOnly、Secure、SameSite 属性降低会话被窃取的风险，配合内容安全策略（CSP）限制脚本来源，并在前端框架中利用其默认的转义机制，避免使用危险的 innerHTML 等接口拼接不可信数据。

#### 什么是 CSRF 跨站请求伪造，如何防范？
CSRF 是攻击者诱导已登录目标网站的用户，在其不知情的情况下以该用户身份发起请求，从而执行非本意的操作，如转账、改密。它利用的是网站仅凭 Cookie 自动携带的身份凭证来识别用户，而无法判断请求是否出于用户真实意愿。防范的关键是增加攻击者无法伪造的校验机制：使用 CSRF Token，在表单或请求头中携带随机令牌并由服务端校验；设置 SameSite Cookie 属性限制跨站请求携带 Cookie；对敏感操作要求二次验证（如验证码、密码确认）；校验 Referer 或 Origin 头作为辅助手段。多种方式结合可有效阻断伪造请求。

#### 文件上传漏洞的成因与防护措施是什么？
文件上传漏洞是指应用允许上传文件但未严格校验，攻击者上传可执行的脚本文件（如 WebShell）并通过 URL 访问执行，进而获取服务器权限。常见绕过手段包括伪造扩展名、修改 Content-Type、利用解析漏洞、上传特殊可解析文件等。防护应在服务端做严格校验：采用白名单限制允许的文件类型，不能仅依赖前端校验或 Content-Type；对上传文件重命名并存储到 Web 目录之外，禁止上传目录具备执行权限；对文件内容进行校验，判断真实文件类型；及时修补中间件的解析漏洞，并以最小权限运行服务，降低漏洞被利用后的影响范围。

#### 什么是命令执行漏洞，如何防范？
命令执行漏洞是指应用将用户可控输入传入系统命令或动态执行函数，攻击者通过命令拼接（如命令分隔符、管道符、反引号等）注入并执行任意系统命令，可能导致服务器被完全控制。它常出现在调用系统工具、ping 检测、文件处理等功能中。防范首先应尽量避免直接调用操作系统命令，优先使用语言内置的安全 API；确需调用时，避免使用会触发 shell 解析的方式，采用参数数组形式传参而非拼接字符串；对输入做严格的白名单校验和字符过滤，禁止命令分隔符等特殊字符；同时以最小权限运行服务，并通过补丁更新、主机加固和监控告警限制漏洞影响。
